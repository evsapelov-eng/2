# PLUIT Assistent

Личный помощник автора канала [PLUIT Club](https://t.me/pluit_club). Читает
комментарии в обсуждениях, отмечает те, на которые стоит ответить, предлагает
вариант ответа в стиле автора и собирает идеи для постов. Сам никому не пишет и
ничего не публикует. Пишет только владельцу в личный чат.

Работает бесплатно и без сервера: пять раз в день его запускает GitHub Actions,
данные хранятся в зашифрованном виде в ветке `bot-state` этого же приватного
репозитория.

- Архитектура, решения и риски: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)
- Данные и конфиденциальность: [docs/PRIVACY.md](docs/PRIVACY.md)
- Правила проекта для Claude Code: [CLAUDE.md](CLAUDE.md)

## Что важно знать заранее

- **Бот отвечает не мгновенно.** Проверки идут в 09:00, 12:00, 15:00, 18:00 и
  21:00 по Москве, GitHub иногда запускает их с опозданием. Команды и кнопки
  срабатывают при ближайшей проверке. Сразу работает только кнопка «Открыть
  комментарий». Внеплановую проверку можно запустить вручную: GitHub → Actions →
  PLUIT Assistent → Run workflow (это можно сделать и из мобильного приложения
  GitHub).
- **Сутки без запусков — потеря комментариев.** Telegram хранит необработанные
  обновления не больше 24 часов. Если Actions не запускался дольше, комментарии за
  этот период боту недоступны. Старую переписку Bot API не отдаёт.
- **Gemini на бесплатном тарифе** может использовать переданные тексты для улучшения
  продуктов Google. Имена подписчиков в Gemini не передаются. Без ключа Gemini бот
  работает по простым правилам, но без вариантов ответа. Подробнее в
  [docs/PRIVACY.md](docs/PRIVACY.md).
- **Ночью уведомлений нет** (23:00–09:00). Если интересных комментариев нет, бот
  молчит.

## Установка

Понадобятся Telegram, аккаунт GitHub и (по желанию) аккаунт Google для ключа Gemini.
Компьютер нужен только на время настройки.

### 1. Репозиторий

Создайте **приватный** репозиторий `pluit-assistent` и положите в его корень
содержимое этой папки (вместе со скрытой папкой `.github`). Если проект лежит
подпапкой `pluit-assistent/` в другом репозитории:

```bash
git subtree split --prefix=pluit-assistent -b pluit-assistent-only
git push git@github.com:<ваш-логин>/pluit-assistent.git pluit-assistent-only:main
```

Расписание GitHub Actions работает только из ветки по умолчанию (`main`).

### 2. Бот в Telegram

1. В [@BotFather](https://t.me/BotFather): `/newbot`, отображаемое имя
   `PLUIT Assistent`, username — любой свободный (например `pluit_assistent_bot`).
   Сохраните токен.
2. Там же: `/setprivacy` → выберите бота → **Disable**. Так бот видит все
   комментарии без прав администратора. Если бот уже был в группе, удалите его и
   добавьте снова: настройка применяется при добавлении.
3. Добавьте бота **обычным участником** в группу обсуждений, привязанную к каналу
   PLUIT Club. Права администратора не нужны: ни публикация, ни удаление, ни
   блокировка. Если группа не даёт добавить участника без прав, назначьте бота
   администратором и **выключите все права**.
4. Откройте личный диалог с ботом и нажмите **«Старт»**: без этого бот не сможет
   вам написать.

### 3. Идентификаторы

1. Оставьте тестовый комментарий под любым постом канала и напишите боту
   что-нибудь в личку.
2. Откройте в браузере `https://api.telegram.org/bot<ТОКЕН>/getUpdates`. Это
   безопасно: просмотр не удаляет обновления. Ссылку никому не пересылайте, в ней
   токен.
3. Найдите в ответе:
   - `OWNER_TELEGRAM_ID` — `message.from.id` в вашем личном сообщении боту;
   - `DISCUSSION_GROUP_ID` — `message.chat.id` у комментария (вида `-100…`);
   - `CHANNEL_ID` — `forward_origin.chat.id` у автоматически пересланного поста
     (`is_automatic_forward: true`) или `sender_chat.id` поста (вида `-100…`).

   Если пересланного поста в ответе нет, опубликуйте в канале новый пост и обновите
   страницу.

### 4. Ключ Gemini (по желанию)

1. Откройте [Google AI Studio](https://aistudio.google.com/apikey) и создайте ключ
   в проекте **без подключённого биллинга**. Тогда платные запросы невозможны в
   принципе.
2. В AI Studio → Rate limits проверьте, какие модели доступны бесплатно, и при
   необходимости поменяйте `gemini_model` и `gemini_fallback_model` в
   `config/settings.yaml`.

Gemini API официально доступен не во всех странах. Перед созданием ключа сверьтесь
со [списком регионов](https://ai.google.dev/gemini-api/docs/available-regions) и
[условиями](https://ai.google.dev/gemini-api/terms). Без ключа бот тоже работает.

### 5. Ключ шифрования

```bash
python scripts/generate_key.py
```

Сохраните вывод в менеджере паролей: без этого ключа накопленные данные не
восстановить.

### 6. Секреты GitHub

Settings → Secrets and variables → Actions → **New repository secret**:

| Секрет | Значение |
|---|---|
| `TELEGRAM_BOT_TOKEN` | токен от BotFather |
| `GEMINI_API_KEY` | ключ AI Studio (можно не задавать) |
| `OWNER_TELEGRAM_ID` | ваш Telegram ID |
| `CHANNEL_ID` | ID канала, `-100…` |
| `DISCUSSION_GROUP_ID` | ID группы обсуждений, `-100…` |
| `STATE_ENCRYPTION_KEY` | вывод `generate_key.py` |

Секреты вводятся только в GitHub, никуда их не пересылайте.

### 7. Проверка и запуск

1. Actions → включите workflows, если GitHub спросит.
2. Actions → **Проверка настройки** → Run workflow. Скрипт проверит токен, Privacy
   Mode, группу, привязку к каналу и права бота и пришлёт вам тестовое сообщение.
   Галочка «Сделать один тестовый запрос к Gemini» расходует один запрос квоты.
3. Actions → **PLUIT Assistent** → Run workflow — первый запуск. Он создаст ветку
   `bot-state`. Дальше бот работает по расписанию.
4. Напишите боту `/start`: меню придёт при ближайшей проверке.

Защита веток (branch protection) не должна распространяться на `bot-state`: бот
перезаписывает её при каждом сохранении.

## Команды

| Команда | Что делает |
|---|---|
| `/start` | запуск помощника |
| `/menu` | главное меню |
| `/inbox` | входящие комментарии |
| `/stats` | аналитика |
| `/archive` | архив публикаций |
| `/ideas` | идеи для постов |
| `/settings` | настройки |
| `/digest` | текущая сводка |
| `/pause`, `/resume` | приостановить или возобновить уведомления |
| `/status` | состояние системы |
| `/forget <ID или @username>` | удалить данные подписчика |
| `/help` | помощь |

Команды видны и работают только в личном чате владельца. Посторонний пользователь
получает отказ.

## Режимы уведомлений

- **Умный** — до 5 карточек при каждой плановой проверке. Звук только у первой.
- **Дайджест** — один отчёт на вечерней проверке (21:00).
- **Тихий** — сбор и анализ без уведомлений, всё лежит во «Входящих».

По понедельникам на проверке в 12:00 приходят «Итоги недели», если за неделю были
комментарии.

## Настройки

**В меню бота (Настройки):** режим, порог приоритета (по умолчанию 70), число
рекомендаций за проверку, вечерняя сводка, еженедельный отчёт, длина и обращение в
предлагаемых ответах, срок хранения комментариев, приостановка AI-анализа и
уведомлений.

**В репозитории:**

- `config/settings.yaml` — модели Gemini, лимиты, тихие часы, окно быстрых ответов;
- `config/author_profile.yaml` — профиль и стиль автора, запрещённые фразы;
- `.github/workflows/bot.yml` — расписание. Если меняете его, обновите
  `schedule_cron` в `settings.yaml`: по нему считается подсказка «следующая
  проверка».

Значения из `settings.yaml` можно переопределить переменными репозитория
(Settings → Variables → Actions): `GEMINI_MODEL`, `NOTIFICATION_THRESHOLD`,
`NOTIFICATION_MODE`, `MAX_AI_REQUESTS_PER_DAY` и другие из `bot.yml`.

## Импорт старых постов

Архив пополняется автоматически с момента подключения. Старые посты можно добавить
вручную: положите файл `data/import_posts.json` в репозиторий. Это публичные посты
канала, личных данных в них нет. Подходят два формата:

- список `[{"id": 120, "date": "2026-10-01T12:00:00+03:00", "text": "…"}]`, где
  `id` — номер поста в канале (из ссылки `t.me/pluit_club/120`);
- `result.json` из экспорта канала в Telegram Desktop.

Файл импортируется при ближайшем запуске, повторно — только если изменился.
Существующие посты не перезаписываются.

## Расход бесплатных квот

| Ресурс | Расход | Лимит |
|---|---|---|
| GitHub Actions | ~155 запусков × 1–2 мин ≈ 150–310 мин/мес + тесты | 2000 мин/мес для приватных репозиториев на Free (проверьте в Billing) |
| Gemini | до 10 запросов за запуск, до 18 в сутки на модель, до 8 комментариев в запросе | бесплатный лимит модели (около 20 в сутки) |
| Telegram Bot API | бесплатно | — |

Если квота Gemini исчерпана, комментарии ждут следующего дня. Через 6 часов
ожидания бот оценивает их по правилам, чтобы важное не потерялось. Автоматического
перехода на платные модели нет.

## Обслуживание

- **Состояние системы:** `/status` в боте или журнал запуска в Actions (там только
  счётчики, без текстов).
- **Сбросить данные:** удалите ветку `bot-state`, и следующий запуск начнёт с нуля.
- **Сменить ключ шифрования:** только вместе со сбросом данных.
- **Посмотреть состояние локально:** `scripts/inspect_state.py` (выводит только
  счётчики).

## Разработка

```bash
python -m venv .venv && . .venv/bin/activate
pip install -e ".[dev]"
ruff check . && pytest
```

Тесты не ходят в сеть: Telegram и Gemini подменяются, тест ветки состояния
работает с локальным git-репозиторием. Локальный запуск с настоящим ботом:
скопируйте `.env.example` в `.env`, заполните, выставьте `STATE_BACKEND=local` и
запустите `set -a; . ./.env; set +a; python -m app.main`. Не запускайте локально
бота, который уже работает в Actions: два экземпляра заберут друг у друга
обновления.
