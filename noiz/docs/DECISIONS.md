# NØIZ — противоречия ТЗ и принятые решения

Каждое решение ссылается на раздел ТЗ (`docs/NOIZ_MASTER_SPEC.md`). Если решение надо пересмотреть, меняем его здесь и в коде одновременно.

| ID | Противоречие / пробел | Решение |
|---|---|---|
| D1 | Эскизы показывают MAIN/ENV/FILTER/FX, ADSR, HPF/LPF, TEXTURE/CHARACTER — в DSP есть только 4 макроса (§03, §17). | На главном экране только 4 ноды. Фильтр/ресонанс/шумовой микс — в будущем ADVANCED и только там, где параметр реально есть в DSP. |
| D2 | §10: Envelope «редактируемая», но единственный параметр огибающей — DECAY. | Огибающая показывается (будущий Sound-экран), вычисляется из DECAY, отдельно не редактируется. |
| D3 | Концепт: VARIATION 25% и AMOUNT 25% одновременно; §10 запрещает дублировать. | Один глобальный AMOUNT (footer / правый блок). Справа у дорожки — LENGTH, DIVISION, DENSITY. |
| D4 | Дефолты: JSON §05 (0.64/0.29/…/−9 dB) ≠ таблица §07 (68/20/45/10, −12 dB). | Берём таблицу §07; JSON §05 — иллюстрация схемы. |
| D5 | Не сказано, обновляет ли Generate опорную точку Keep. | Generate делает результат новым Keep-anchor, иначе Mutate после Generate «откатывал» бы к старому паттерну (US-02). Undo возвращает и anchor. |
| D6 | Нет места в эскизах для: scope, Lock Density/Amount, Lock Rhythm/Sound, страниц 17–32, выбора голоса в Compact. | Scope — 4 переключателя RHY/SND/PLK/ALL; LK DENS/LK AMT появляются при scope PLK/ALL; на каждой дорожке флажки M / R / S (mute, lock rhythm, lock sound); переключатель страниц 1/2; клик по имени дорожки — выбор голоса. |
| D7 | Compact на эскизе 1280 px, в ТЗ 360–640; полный экран на эскизе 1600×920, в ТЗ 1440×860. | Цифры ТЗ. Текущий диагностический UI — 760×169 (помечен DIAGNOSTIC, §16.5); финальный Compact ≤ 640 — P5. |
| D8 | Сохранение Undo-истории в Live Set (§05) раздует blob в ~16 раз. | Сохраняются состояние, Keep-anchor и счётчик генераций. Undo-стек живёт в сессии (политика «в пределах выбранной», §05). |
| D9 | «Применять на следующем такте» при полиметрии — какой такт? | Такт Live 4/4 (4 доли), а не циклы дорожек. v1 предполагает размер 4/4 (как базовая сетка §06). Другие размеры — известное ограничение. |
| D10 | ▶ ■ в footer эскиза, но BPM/транспорт — Live. | Кнопок транспорта нет: секвенсор всегда идёт от Live (A03). |
| D11 | Mutate с Amount=0 «точное отсутствие изменений» (A07) vs «Mutate от anchor». | Amount=0 — строгий no-op без записи в Undo, даже если текущее состояние отличается от anchor. |
| D12 | Mutate для одних частей (например RHYTHM) не должен откатывать другие части к anchor. | Из anchor берутся только части в scope и не залоченные; остальное — текущее состояние. |
| D13 | Rhythm-операции и P-Locks: Lock Sound включает P-Locks (§08). | Ритмические операции не трогают `pLocks` вообще; P-Lock «спит» на выключенном шаге. |
| D14 | Level / Mute и Undo. | Микшерные настройки не пишутся в Undo NØIZ (Live сам отменяет изменения маппленных параметров). Generate/Mutate никогда не меняют level/mute. |
| D15 | Тайминг: `[js]` в Max работает в низкоприоритетном потоке. | Lookahead-планировщик: JS считает события на 40 мс вперёд от позиции Live, `[pipe]` (высокий приоритет) выпускает их вовремя. Петля Live учитывается, seek/stop → `clear` очереди. См. `docs/ARCHITECTURE.md`. |
| D16 | Ratchet в слишком коротком шаге (§06). | Минимальный интервал субудара 12 мс; если не помещается — число субударов уменьшается до максимально возможного (≥ 1). |
| D17 | Каждое событие должно звучать со своими P-Lock-значениями, не трогая хвосты (§07). | `poly~`: один экземпляр голоса на удар (8 на голос, `@steal 1`), параметры приходят вместе с триггером. |
| D18 | Mute без щелчков (§07). | Mute = новые удары не запускаются, уже звучащие хвосты доигрывают естественно. |
| D19 | Velocity → громкость. | amp = velocity^1.5 · dB→amp(level); огибающая квадратичная, на `line~` подаётся √amp. |
| D20 | Компенсация громкости DRIVE. | comp = g^−0.6, g = 1 + 14·drive — подобрано измерением в `tools/render_voices.js` (разброс RMS ≤ 4 дБ по всем голосам). |
| D21 | §16.1: не выдавать скриптовый `.amxd` за проверенный плагин vs запрос пользователя «соберите готовый инструмент, протестирую сам». | Собираем тестовую сборку `dist/NOIZ/*.amxd` скриптом (контейнер `ampf`, тип `iiii` = Instrument). Везде помечена как НЕ проверенная в Live; штатный путь (Save в Live) остаётся запасным в `HOST_TEST_GUIDE.md`. |
| D22 | v0.2: запрос пользователя упростить интерфейс. | Удалены RHY/SND/PLK/ALL, LK DENS, LK AMT, DENS, R/S, BASE. Область GENERATE/MUTATE задаётся экраном (SEQ → PATTERN = ритм + P-Locks, SYNTH → SOUND). R+S → одна L. |
| D23 | Панорама как часть генерации (запрос пользователя). | PAN — 5-й P-Lock-параметр (0..1). SPREAD — детерминированный разброс на удар; ratchet-субудары проходят по базе. Панорама равной мощности на экземпляр poly~, центр = уровень v0.1 (√2·cos/sin). |
| D24 | Модуль синтеза (запрос пользователя). | Экран SYNTH: TONE, DECAY, TEXTURE, DRIVE, RESO, ATTACK, CHARACTER (у голоса свой смысл), PAN, SPREAD, LEVEL. Не залочиваются по шагам: RESO, ATTACK, CHARACTER, SPREAD, LEVEL. ADSR/многорежимные фильтры не вводились — каждый параметр должен иметь проверяемую связь с DSP (§17). |
| D25 | Схема данных изменилась (pan, synth). | schemaVersion 2; Live Sets v1 мигрируют: паттерн сохраняется, pan/synth получают значения по умолчанию, звучание не меняется. |
| D26 | v0.3: «при рандоме должны меняться все параметры, включая синтез». | GENERATE и MUTATE всегда работают в области ALL (ритм, звук, синтез, P-Locks) на любом экране; защита — только L. Заменяет D22 в части области по экрану. |
| D27 | «Параметры на каждый шаг у каждого инструмента». | Все 9 параметров (tone, decay, texture, drive, pan, reso, attack, character, spread) лочатся по шагам; новый экран LANE — рисование значений по шагам; SYNTH в режиме STEP пишет P-Locks шага. LEVEL остаётся параметром голоса (громкость шага = VEL). Случайные P-Locks затрагивают все 9. |
| D28 | «Визуальный язык должен быть полностью понятен». | Картинка SYNTH считается той же ES5-моделью голоса, что и офлайн-проверки (`js/shared/noiz_dsp_model.js`), — не декорация. У каждой ноды свой знак по смыслу параметра. Тест доказывает, что каждая из 10 ручек меняет картинку. Пересчёт ≤ 1 раз в 90 мс; стоимость в Max проверить (в Node 12–42 мс). |
| D29 | «Пошаговые параметры при GENERATE должны каждый раз давать разные значения и рисунок». | Случайные P-Locks заменены дорожками: для каждого параметра с вероятностью lockDensity (0.75) рисуется значение на каждом шаге цикла; 6 форм, случайная глубина в пределах параметра, форма не выходит за 0..1. Базовая ручка голоса сдвигает дорожку (D30 ниже не нужен: смысл ручки сохраняется). Схема v3. |
| D30 | «После каждого GENERATE и MUTATE должны меняться все показатели каждого инструмента». | GENERATE: lockDensity = 1 — все 9 дорожек у каждого голоса без L. MUTATE: каждое значение (база звука и синтеза, каждый шаг каждой дорожки) сдвигается минимум на 0.01 и обязано отличаться от звучавшего перед нажатием (не только от Keep). AMOUNT = 0 остаётся «без изменений» (A07). Схема v4. |
