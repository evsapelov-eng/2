# Milestone 0 — протокол испытания spike-устройства в Ableton Live 12
\n> **Обновление M1:** эти эксперименты теперь выполняются автоматически кнопкой `self_test` в основном устройстве FLOW (см. USER_GUIDE_RU.md, раздел 2). Этот протокол и spike-устройство оставлены для ручной диагностики.

Статус устройства: **UNVERIFIED**. Его ещё ни разу не открывали в Live: среда разработки — Linux-контейнер без Ableton и Max. Это измерительный прибор, а не FLOW. **На концерте не использовать.**

Цель: на вашем Mac получить факты, от которых зависит архитектура FLOW (§6, §7, §8 ТЗ). Пока этот протокол не выполнен, к Milestone 1 переходить нельзя.

## 1. Что нужно

- macOS, Ableton Live 12 Suite (или Standard + Max for Live), встроенный Max.
- Запишите: версию Live (`Live → About Live`) и версию Max (в редакторе Max: `Max → About Max`).
- Digitone **не нужен**. Отключите его, чтобы исключить влияние внешнего клока.

## 2. Тестовый Live Set (создать один раз и сохранить как `FLOW-M0-Test.als`)

1. Новый Set, 120 BPM, 4/4. Включите метроном: тогда переходы будет слышно.
2. Аудиодорожка: любой длинный непрерывный звук или луп на 32+ такта в Arrangement, начиная с такта 1.
3. MIDI-дорожка с инструментом и MIDI-клипом в Arrangement на такты 1–33, где каждый такт начинается с другой ноты (например, такт N → нота C3+N). Это позволит на слух и по MIDI определить, какой такт играет.
4. Локаторы (`Create → Add Locator`) на тактах 1, 9, 17, 25 с именами `INTRO`, `GROOVE`, `BREAK`, `DROP`.
5. Arrangement Loop изначально выключен.
6. Global Quantization (`clip_trigger_quantization`) = **1 Bar**.

## 3. Установка устройства

### Вариант A — готовый `.amxd` (может не открыться: бинарная обёртка собрана без Max)

1. Скопируйте **всю** папку `flow/dist/` (там `FLOW-M0-Spike.amxd` и `flow_spike.js`), например, в
   `~/Music/Ableton/User Library/Presets/MIDI Effects/Max MIDI Effect/FLOW-M0/`.
2. Перетащите `FLOW-M0-Spike.amxd` на **MIDI-дорожку** из пункта 2.3 (до инструмента).
3. Откройте Max Console (правый клик по заголовку устройства → `Open Max Window`). Должна появиться строка
   `FLOW [..ms] FLOW m0-spike 0.1.0 initialised. Transport untouched on load.`

### Вариант B — ручная сборка (если A не открылся или пишет ошибку)

1. На MIDI-дорожку перетащите стандартный `Max MIDI Effect` (Browser → Max for Live).
2. Кнопка `Edit` откроет редактор Max. Перейдите в режим редактирования (Cmd+E), выделите всё (Cmd+A) и удалите стандартные `midiin`/`midiout`: наш патч содержит свои, а дубли удвоят MIDI.
3. Откройте `flow/device/m0-spike/flow-spike.maxpat` в Max (`File → Open`), разблокируйте, Cmd+A, Cmd+C; вставьте в патч устройства (Cmd+V).
4. `File → Save As…` в папку, где лежит `flow_spike.js` (`flow/device/m0-spike/`), например как `FLOW-M0-Spike.amxd`.
5. Если в консоли есть `js: can't find file flow_spike.js`: добавьте эту папку в `Options → File Preferences` или нажмите `Freeze Device` в редакторе и сохраните снова.
6. Закройте редактор. Проверьте строку `initialised` в Max Console.

**Запишите, какой вариант сработал** (A или B) и все ошибки консоли: это результат для T01 и для сборки.

## 4. Элементы устройства

Слева 4 строки статуса: позиция/темп, состояние Loop, результат эксперимента, предупреждения. Ниже: `target bar`, `cue #`, `save log`. Справа сетка кнопок (это message box, нажимаются кликом).

| Кнопка | Действие |
|---|---|
| `read` / `cuelist` | Вывести в лог все свойства Song и локаторы |
| `play` / `stop` | `continue_playing` / `stop_playing` |
| `loopon` / `loopoff` | `Song.loop = 1/0` |
| `restore` | Вернуть loop/loop_start/loop_length из последнего снимка |
| `backtoarr` | `back_to_arranger = 0` |
| `seek` / `cuejump` | `current_song_time` = начало `target bar` / `CuePoint[cue #].jump()` |
| `abort` | Прервать эксперимент |
| `poll 1/0` | Дополнительно опрашивать `current_song_time` каждые 5 мс |
| `verbose 1/0` | Подробный лог каждого SET |

## 5. Эксперименты (выполнять по порядку, результат — строки `EXP … RESULT` в логе)

Перед каждым экспериментом запустите воспроизведение с такта 1 (кроме E2 и E10).

| # | Кнопка | Что проверяем | Что записать |
|---|---|---|---|
| E0 | `read`, `cuelist` | Чтение Song.* и `cue_points` (name/time) | Совпадают ли значения с экраном Live; видны ли 4 локатора с верными тактами |
| E1 | `exp_rates 10` | Как часто приходят уведомления `current_song_time`, как часто меняется значение при опросе, реальный период Task | Строки `RATES …` целиком |
| E2 | `exp_bars` при **остановленном** транспорте, playhead на такте 5.3 | Перевод beats → такты (`num*4/den`) против Live | PASS/MISMATCH. Повторить в 3/4 и 6/8 |
| E3 | `exp_hold 1`, затем `exp_hold 4` | HOLD: Live реально повторяет участок; задержка readback/observer | PASS, строки `HOLD wrap …`; **на слух**: аудио и MIDI продолжают звучать, без щелчков? |
| E4 | после E3: `exp_release` | RELEASE: `loop=0` до границы → линейное продолжение без лишнего оборота | PASS/EXTRA CYCLE, `remaining_to_end_ms`. Повторить 10 раз (T06), нажимая в разных местах цикла |
| E5 | `exp_release_sweep 1 3` | Минимальный безопасный запас времени для RELEASE (1000…15 мс) | Все строки `SWEEP SUMMARY` и `RECOMMENDED_RELEASE_LEAD_MS` |
| E6 | `exp_hold_sweep 1 2` | Позднее включение петли; **отрицательные** запасы показывают, прыгает ли Live назад, если loop включён после прохождения конца | Строки `HOLDSWEEP SUMMARY` (HELD/MISSED/JUMPED_BACK/NO_JUMP) |
| E7 | `target bar` = 2, `exp_seek` во время игры на такте ~3.2 | Прыжок по `current_song_time`: мгновенный или квантованный | `LIKELY_IMMEDIATE`/`LIKELY_QUANTIZED`, `latency`. **На слух**: щелчок, обрыв хвостов? Повторить с Global Quantization = None |
| E8 | `cue #` = 2, `exp_cuejump` | `CuePoint.jump` (документирован как квантованный) | Класс, `latency`, `last_pre` (должен быть у границы такта) |
| E9 | играть с такта 6, `target bar` = 1, `exp_wrapjump` | Нативный прыжок назад через петлю `[target, следующий такт)` | PASS, `jumped at`, `landed`; на слух — переход ровно на сильную долю? |
| E10 | `exp_notifyset` | Можно ли менять Live из колбэка observer'а (ожидается: нельзя) | Строка `NOTIFYSET …` и ошибки в консоли |
| E11 | Вручную: во время `exp_hold 4` передвиньте Loop brace мышью | Видит ли устройство внешнее изменение (строки `OBS` при `verbose 1`) | Есть ли уведомления `loop_start`/`loop_length` |
| E12 | Вручную: запустите Session-клип на дорожке, которая играет Arrangement | Срабатывает ли `WARN back_to_arranger=1`; работает ли `backtoarr` | Да/нет |
| E13 | Сохраните Set, закройте, откройте снова | Устройство не запускает транспорт и не меняет Loop при загрузке | Да/нет |

Матрица (§18 ТЗ) для E3–E6: темп **80 / 120 / 160**, длины **1 / 4 / 8** тактов (`exp_hold 8`, `exp_release_sweep 8 3`). Минимум для решения по архитектуре: E1, E3, E4, E5, E6, E7, E8, E9 при 120 BPM, и E5 при 80 и 160.

## 6. Как передать результаты

1. Нажмите `save log` и сохраните файл (например, `flow-m0-log-120bpm.txt`).
2. Добавьте версии Live/Max, вариант установки (A/B), слуховые наблюдения по E3/E4/E7/E9.
3. Передайте файл(ы) в следующую сессию. Я перенесу факты в `docs/TEST_RESULTS.md` и `docs/API_VERIFICATION.md` и только после этого начну Milestone 1.

## 7. Безопасность

- Устройство меняет только `loop`, `loop_start`, `loop_length`, `current_song_time`, `is_playing`, `back_to_arranger`, и только по кнопкам. Клипы, локаторы и автоматизацию оно не создаёт и не меняет.
- Снимок Loop делается при загрузке и перед экспериментами; `restore` возвращает его.
- Эксперименты, которые прыгают по таймлайну (E5, E7–E9), используйте только на тестовом Set.
